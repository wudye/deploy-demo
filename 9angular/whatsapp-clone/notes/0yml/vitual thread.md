虚拟线程是轻量级线程，运行在传统的操作系统线程（平台线程）之上，由 JVM 管理，可以高效创建数百万个虚拟线程。


// 传统线程处理 10,000 个并发请求
ExecutorService executor = Executors.newFixedThreadPool(200); // 200 个线程

for (int i = 0; i < 10000; i++) {
executor.submit(() -> {
// 模拟数据库查询（I/O 操作）
try {
Thread.sleep(100); // 阻塞 100 毫秒
} catch (InterruptedException e) {
e.printStackTrace();
}
});
}
请求 1 → 线程 1 → 等待数据库响应（阻塞）
请求 2 → 线程 2 → 等待数据库响应（阻塞）
...
请求 200 → 线程 200 → 等待数据库响应（阻塞）
请求 201 → ⚠️ 需要等待线程 1-200 中的某个完成

指标	传统线程	虚拟线程
并发请求数	200	100,000+
内存占用	~200MB	~20MB
响应时间	500ms（排队等待）	100ms（即时响应）
吞吐量	400 req/s	100,000 req/s
虚拟线程 vs 平台线程
核心对比表
特性	平台线程（传统）	虚拟线程（Java 21+）
创建成本	高（约 1MB 栈内存）	极低（几 KB）
创建数量	数百到数千	数百万
阻塞行为	阻塞操作系统线程	不阻塞，挂起并释放底层线程
调度器	操作系统	JVM（轻量级）
适用场景	CPU 密集型	I/O 密集型
API 兼容性	-	完全兼容现有代码#

阻塞行为对比
传统线程阻塞：

虚拟线程 1 → 执行 → 遇到 I/O 阻塞（数据库查询）
↓
底层平台线程被阻塞（占用资源）
↓
无法处理其他请求
↓
性能瓶颈
虚拟线程阻塞：

虚拟线程 1 → 执行 → 遇到 I/O 阻塞（数据库查询）
↓
挂起虚拟线程（释放平台线程）
↓
平台线程可以处理其他虚拟线程
↓
I/O 完成后恢复虚拟线程
↓
高效利用资源
